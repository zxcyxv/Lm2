## Question

At the current checkpoint, does committing four continuously composed byte
predictions per canonical re-encoding visibly break generation relative to
the same model's ordinary greedy one-byte AR path?

## Fixed protocol

- data: the parent experiment's checksummed WikiText-103 validation byte
  stream; test is not used
- seed: `1337 + 2024`
- three fixed examples, 256 prompt bytes and 64 generated bytes
- greedy AR: one generated byte followed by canonical re-encoding
- block-4: within each block use
  `u_(j+1) = K(u_j)u_j` for four states with no hard-token feedback, then
  append all four selected bytes and canonically re-encode at the boundary
- both paths use a rolling 256-byte context and identical prompts
- strict float32 with TF32 disabled

## Readouts

- literal generated bytes rendered with invalid UTF-8 escaped as `\\xNN`
- strict UTF-8 validity, replacement-character count, printable ASCII/space
  fraction, token diversity, and immediate repetition per sample
- block-4 versus greedy-AR byte agreement and matching-prefix length

The audit counts the current block-4 path as clearly non-equivalent to AR if
mean byte agreement is below `0.80`. It counts byte-level rendering as
severely broken if fewer than half of block-4 samples are strict-valid UTF-8.
These are separate claims: disagreement with AR alone does not prove that an
independently generated continuation is unreadable.

Numeric outputs go to TSV; byte renderings and interpretation go to Markdown.

## Post-run scope

The AR-equivalence criterion failed: mean block-4/AR byte agreement was
`0.098958`, with a mean matching prefix of one byte. The preregistered strict
UTF-8 breakage criterion did not trigger: all three block-4 samples were
strict-valid, printable ASCII. This conflicting evidence is retained rather
than collapsed into one label. Despite valid encoding, natural-language
quality was visibly degenerate and immediate byte repetition was `0.661376`
versus `0.010582` for greedy AR.
