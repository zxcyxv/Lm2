## Question and comparison

How does actual continuation quality change when generated byte tokens are
re-entered every 1, 2, 4, 8, or 16 tokens?  Compare all block sizes on the
same prompts under greedy decoding and fixed top-p sampling.

## Fixed protocol

- seed 1337; 64 preserved validation starts
- 256-byte prompt and 128-byte continuation
- block sizes 1, 2, 4, 8, and 16
- after every block, append its bytes and re-encode the resulting context
- greedy and temperature-0.8/top-p-0.9 sampling
- distinct fixed CUDA sampling seed per block size
- actual final prefix position 255 as the central root
- report entropy, diversity, whitespace, UTF-8 validity, repetition, aligned
  accuracy, exact-prefix length, and cross-prompt collapse
- report every within-block phase separately
- store reversible hex and escaped text for twelve identical prompts
- metrics are TSV and interpretation is Markdown

## Interpretation gates

- judge sentence quality from samples plus collapse/repetition metrics, not
  long aligned-reference accuracy alone
- distinguish greedy mode collapse from distributional failure under sampling
- distinguish byte diversity from coherent words and syntax
- do not treat block sampling as autoregressive-equivalent: sampled bytes
  inside a block are not re-entered until the next block
